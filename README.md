# 余烬边境 · Ember Marches

一个受经典浏览器地牢探险游戏玩法启发、**数据驱动**的多人在线 RPG 框架。

你负责世界：过往、武器、技能、装备、怪物、迷宫全部写在 `content/*.json` 里；
框架负责账号、英雄、实时远征、回合制战斗、掉落、成长、排行与存档。

> 代码与示例内容均为原创，不包含原站代码、素材或文本。若要公开发布，请自行确认名称、商标与内容版权。

## 特性

- **单中文服务器**：账号注册 / 登录、Cookie 会话、SQLite 持久化、共享排行榜；界面仅中文，无世界/服务器选择。
- **一人一号**：默认同一网络只能注册一个账号；单账号最多 **5 名英雄**（创建时从全部过往抽 2 个、武器路径抽 3 个供选择；草稿刷新、重启或超时仍保留候选，每次创建机会最多一次免费明确重抽，创建或重抽失败不消耗机会；可付 100 金币输入全名删除英雄）。多人共用网络可开启共享网络模式。
- **数据驱动内容**：11 个过往、8 条武器路径、125 个技能、126 件装备、95 种怪物、19 座迷宫（4 座基础副本 + 3 条进阶系列 × 5 层），全部可替换。
- **真实时间远征**：**3–4 人队伍准入**（单人快速派遣或多玩家组队，单账号也可填满）→ 倒计时 → 服务端结算 → 战报 / EP / 金币 / 装备。
- **自选路线迷宫**：每座迷宫是房间图（入口/战斗/宝箱/boss），出发时自选路径或用最短通路；按**怪物等级**判定准入，队伍平均等级最多可低于怪物 5 级；战力只作怪物强度参考。提前收队保留已清房掉落但没有全通奖励；路线选择按玩家记忆保存。
- **战力与怪物强度**：英雄战力由等级、属性、技能与装备综合计算；迷宫页面展示的是每层怪物的等级与战力参考，准入只看队伍平均等级（允许挑战高 5 级）。
- **纯装备掉落**：迷宫常规战利品为装备与金币，彩票库存券另行结算；没有炼药消耗品、材料与强化系统（v0.11.0 起移除），战斗续航靠房间休整与被动回复。
- **未读战报**：结算后的战报会显示在概览顶部；打开战报后自动标记已读，组队成员各自维护未读状态。
- **结构化战报**：行动卡、回合摘要、伤害/治疗/状态/未命中筛选、AoE 多目标合并（含增益/减益），命中与闪避分开显示，记录每次伤害/治疗后的生命变化与施法者法力消耗；属性 buff/debuff、持续伤害、持续治疗与击倒都会注明施加者与技能来源。
- **原站式回合制战斗**：命中/闪避评分、暴击、打击/斩击/穿刺与元素伤害、护甲/抗性、前后排站位、每回合多行动、冷却/法力/持续效果；种子化可复现。
- **英雄成长（v3）**：基础数值由过往、等级、技能被动与装备派生，**没有属性点分配/重置**；成长决策集中在过往、武器路径、技能树节点与装备获取。
- **装备工作台**：槽位筛选、属性对比、替换确认、跨英雄直接转移；物品等级是硬性装备门槛。
- **武器适配**：武器类型 + 武器熟练度限制装备；技能可声明所需武器，武器不匹配时战斗 AI 自动跳过。
- **战斗预设**：每个英雄最多 5 套预设；保存站位、目标优先级、回合前/先攻/主回合技能顺序、按层覆盖与绑定迷宫。派遣时可直接选预设，未指定则优先使用绑定该迷宫的预设。
- **战斗阶段**：引擎按“回合前 → 主回合”执行，先攻只决定出手顺序；技能可声明可用阶段；游走站位可以绕过敌方前排直击后排。
- **个人迷宫（唯一迷宫）**：每位玩家拥有按账号种子生成的专属迷宫区域（入口 → /dungeons），布局因人而异但威胁与奖励预算一致；7 座迷宫系列（含基础四副本）各生成专属区域，已探索区域永久保留，清理当前最深处（击败首领）后可向更深处拓展。固定内容迷宫只作为生成模板，不再可直接派遣；派遣、组队（使用队长区域）、结算、死亡与彩票掉落共用同一套链路。
- **永久死亡与撤离**：战败时倒地角色永久死亡；死亡名册无容量软锁，不阻止创建或派遣、不因人数多删除死者。死亡角色可免费归档为墓碑，装备回背包；旧赦免/赎回券继续兼容，新彩票不再发复活券。战前配置可设撤离条件——任意角色达成即全员撤离保命。
- **雨蚀彩票**：迷宫胜利或成功撤离且实际清理房间后，按 `min(0.5, 0.06 + 实际清理房间最高怪物等级 × 0.01)` 为每个参战账号结算一次掉落，战报提示；掉率不下调，周出票量仅统计、无软上限。掉落为无号码库存券，未投入跨日保留；玩家自选张数分批投入当前日池，每批最多 10000 张、投入总量不限，每张投入时随机生成 6 个不重复号码（00–30），不可撤销。服务器当地每天 00:00 开奖并自动入账：命中 0/1/2/3/4/5/6 个分别得遗产碎片 1/1/3/10/40/200/1000，4 命中另得训练手记 ×1，5/6 命中另得手记 ×3 与收藏称号「拾光者」/「雨幕见证者」（重复分别加 40/200 碎片）。10 碎片换 1 手记；手记为累计 EP ≤5000、存活且不忙的英雄增加 250 可用 EP，不增加累计 EP 或等级，每英雄最多 3 次。旧 pending 票迁库存，旧 drawn 票保留旧奖励、可手动领取；详见[彩票](docs/wiki/lottery.md)。
- **完整 Web 客户端**：概览、名册、创建、详情、组队大厅、迷宫派遣、战报、市场、公会、竞技场、彩票、背包、图鉴、排行，响应式布局。
- **玩家市场 / 公会 / 1v1 竞技场**：挂单与拍卖成交收 5% 手续费、公会金库与仓库、竞技场积分排名、异步决斗（不给 EP）与战报。
- **世界 / 公会聊天**：轻量轮询频道，发言限流；公会频道需要先加入公会。
- **内容平衡模拟器**：改数值后一键跑 100 场，查看胜率、回合、收益。
- **测试**：引擎单元测试 + 端到端 API 冒烟测试。

## 快速开始

要求 **Node.js ≥ 22.13**（推荐 Node 24，内置 `node:sqlite`，无需原生编译）。

```bash
npm install
npm run dev
```

- 前端（Vite 热更新）：<http://localhost:5173>
- API：<http://localhost:8787/api/health>

首次进入请注册账号。注册赠送 **10 个英雄席位**、**100 金币** 与 **500 EP**。
默认同一网络只能注册一个账号；若多名玩家共用同一出口 IP，请以 `WOD_ALLOW_SHARED_IP=1` 启动。

### 生产模式（单进程）

```bash
npm run build     # 构建前端到 apps/web/dist
npm start         # 服务端同时托管 API 与静态页面
```

打开 <http://localhost:8787>。存档在 `data/wod.db`，删除该文件即可重开一个世界。

### 可选：生成演示存档

```bash
# 需要服务端已启动
node scripts/demo.mjs demo demo123456 --dispatch
```

创建账号 `demo`（密码 `demo123456`）、10 名英雄，并派出一支 6 人远征队。
该脚本需要服务端以 `WOD_ALLOW_SHARED_IP=1` 启动，否则同一网络已有账号时无法再创建 demo 账号。
加 `--wait` 可以等待结算完成。仅用于本地演示，请勿在生产环境使用弱密码账号。

## 游戏循环

1. **招募英雄**：选择过往 + 武器路径；自动获得并装备该路径的初始物品。
2. **组建队伍**：单人快速派遣最多 6 人；组队大厅队伍最多 6 名，单账号只要名册里有足够角色，也可以填满整支队伍。每名英雄可保存最多 5 套战斗预设，派遣时用默认预设或快速切换站位。
3. **派出远征**：选择线路与目标深度；服务端立即用种子模拟所选层数的战斗并锁定英雄，返回时间按线路时长与深度折算。
4. **等待结算**：服务端每 10 秒扫描到期远征，并在任意相关 API 请求时惰性结算，离线也会正常完成。
5. **领取战报**：金币、EP、等级、技能等级、装备、重伤状态写入存档；战斗日志可逐回合查看。
6. **整备再出发**：训练技能等级、换装备、治疗重伤英雄；在市场交易，在公会结识同伴，在竞技场试刀。

### 核心规则摘要

- **派生属性**：最终数值 = 过往基础 + 等级成长 + 技能被动/过往特质 + 装备（含强化）；生命/法力再乘生命%/法力%。没有属性点分配或重置。
- **攻击**：攻击力 = 基础攻击 + 武器伤害；技能量级 = `power + levelScale×等级 + weaponScale×攻击力`，再乘技能等级倍率与出伤修正。
- **命中**：`clamp(1.1×命中 / (命中 + (0.5×闪避)^0.9), 5%, 98%)`；曲线先快后慢。面板显示对同级标准怪物的实际命中率。
- **闪避**：同一公式的守方视角；闪避是平值评分，修正直接加减，不再按小基数百分比缩放。面板显示对同级标准怪物的实际闪避率。
- **暴击**：暴击率不再封顶；每次暴击判定 +50% 伤害。超过 100% 时必定暴击，溢出部分继续判定，每次成功再 +50% 伤害；暴击同时让异常积累 ×(1+暴击次数)。
- **先攻**：先攻（含修正）只决定出手顺序；英雄和怪物每回合各执行一次主要行动，不因等级或阈值突然翻倍。
- **护甲**：只减免打击/斩击/穿刺；减伤率 `护甲 / (护甲 + 4×本次物理伤害)`，上限 90%。护甲对低伤害更有效，对高伤害递减；面板括号内为对同级标准物理攻击的减伤率。
- **抗性**：元素/混沌双通道，来源为过往被动与装备词条，范围 -50%–80%；护甲不减免元素/混沌伤害。
- **行动**：英雄和怪物每回合固定一次主要行动；先攻只决定顺序，普通近战只能攻击敌方前排，游走近战可越过前排但会暴露。
- **物品**：每层按怪物等级准入（队伍平均等级最多低于怪物 5 级），战力仅作怪物强度参考；提前收队保留已清层掉落但没有全通奖励，战败只保留 EP 与金币；只有全通才发放线路完成奖励。
- **强化**：每级 +5% 基础属性/护甲/武器伤害，模板与词缀修正也会同步放大；+10 封顶；费用 `2^当前强化等级`，消耗与装备同级的锻造材料。
- **分解**：普通/精良/稀有/史诗装备分别返还 1/2/4/8 个同级锻造材料，强化投入不返还。
- **效果结算**：每回合开始统一结算 HoT → DoT → 眩晕检查，并推进所有效果持续时间；回合结束只做胜负清算。新施加的控制/持续效果从下一个回合开始生效。
- **冷却**：技能使用后冷却 N 回合（实现上额外 +1 并在回合开始递减）。
- **法力**：每回合恢复 8 点，技能消耗法力；不足时使用不耗法力的普通攻击。
- **EP 成长**：等级阈值 `1000 × (等级−1)²`（上限 40 级）；技能树解锁消耗技能点，技能等级按类别消耗 EP，金币为 EP 的 90%。
- **重伤**：远征中倒下的英雄获得 10 分钟重伤，不能参战；可花 `20 + 等级×5` 金币立即治疗。
- **战利品**：怪物与线路完成掉落表按概率/权重掷骰；稀有度决定词缀数量（普通 0 / 精良 1 / 稀有 2 / 史诗 3）；材料按模板与品质/等级堆叠。组队时金币平均分配，物品按参战成员轮转归属。
- **研究记录**：原站实际框架、字段与差距见 [docs/wod-parity.md](docs/wod-parity.md)。

更完整的公式与内容字段说明见 [docs/content-guide.md](docs/content-guide.md)，
系统分层与数据库/API 说明见 [docs/architecture.md](docs/architecture.md)。


## 内容编辑（最重要的部分）

所有游戏内容都在 `content/`。修改后：

```bash
npm run content:check   # 先校验
npm run simulate        # 再看平衡
# 重启服务端（开发模式下 tsx watch 会自动重启）
```

- **改内容不需要改代码**；只要字段满足 Zod schema。
- 每个内容对象都有稳定的字符串 `id`，被其他文件引用。**不要随意改已有 id**，否则存档里引用该 id 的装备/怪物/武器会失效。
- 装备实例在掉落时保存完整 roll（名称、词缀、数值），所以之后修改装备模板不会重算旧物品；但装备的武器类型限制在穿脱时读取模板。
- 背景故事、描述、名称全部在 JSON 中，可以直接替换成你自己的世界。

字段表、效果类型、完整示例与常见错误见 [docs/content-guide.md](docs/content-guide.md)。

| `WOD_DB` | `<data>/wod.db` | SQLite 文件路径 |
| `WOD_CONTENT_DIR` | `<repo>/content` | 内容包目录 |
| `WOD_TIME_SCALE` | `1` | 远征时长缩放；测试可设 `0.02` |
| `WOD_SECURE_COOKIES` | `0` | HTTPS 部署时设 `1` |
| `WOD_PREMIUM` | `0` | 设为 `1` 时新注册账号标记为进阶（当前仅作账号标记，不影响组队人数） |
| `WOD_ALLOW_SHARED_IP` | `0` | 设为 `1` 时允许同一网络注册多个账号（多人共用网络 / 多玩家测试） |
| `WOD_TRUST_PROXY` | `0` | 反向代理部署时设为 `1`，让注册限制读取真实客户端 IP |

示例：

```bash
PORT=9000 WOD_SECURE_COOKIES=1 npm start
```

## 部署提示

- 单进程运行（SQLite 同步写入）；反向代理（Nginx / Caddy）终止 TLS 后转发到 8787。
- 设置 `WOD_SECURE_COOKIES=1`，并确保站点为 HTTPS。
- 反向代理后面的部署需要设置 `WOD_TRUST_PROXY=1`，否则“一人一号”会把所有玩家看成代理的同一个 IP；仅在服务端不直接暴露公网时开启。
- 静态缓存：`index.html` 与 SPA 回退使用 `no-store`，`assets/*` 使用一年 immutable 缓存；更新后玩家普通刷新即可，不需要 `Ctrl+F5`。
- 备份 `data/wod.db`（以及 WAL 文件）即可完整备份存档。
- 修改内容包后重启服务端；不需要迁移数据库（内容与存档通过 id 关联）。
- 当前版本没有数据库迁移框架；正式迭代前建议引入版本化 migration。
